# راهنمای فرانت‌اند: شماره کارت برای تسویه حساب

این سند فقط تغییرات مربوط به «شماره کارت» را توضیح می‌دهد.

> مسیرهای زیر بر اساس prefix فعلی پروژه (`/api/`) نوشته شده‌اند. اگر فرانت از prefix دیگری مثل `/api/v1/` استفاده می‌کند، همان بخش انتهایی مسیر را حفظ کنید.

## خلاصه تغییرات

- به پروفایل هر کاربر فیلد جدید `card_number` اضافه شده است.
- ثبت درخواست برداشت برای **مالک باشگاه** و **مربی** فقط وقتی انجام می‌شود که شماره کارت داشته باشند.
- شماره کارت را می‌توان از قبل در پروفایل ذخیره کرد، یا همراه همان درخواست برداشت فرستاد.
- ادمین در لیست و جزئیات درخواست‌های برداشت، شماره کارت را می‌بیند.

## ۱) پروفایل کاربر

### دریافت پروفایل

خروجی `GET` پروفایل یک فیلد جدید دارد:

```json
{
  "id": 12,
  "phone": "09121234567",
  "full_name": "علی رضایی",
  "role": "owner",
  "card_number": "6037991234567890"
}
```

- `card_number` می‌تواند `null` باشد؛ یعنی کاربر هنوز شماره کارت ثبت نکرده است.
- این مقدار فقط در پروفایل خود کاربر و پنل ادمین برمی‌گردد و در APIهای عمومی نمایش داده نمی‌شود.

### ذخیره یا ویرایش شماره کارت

از همان endpoint ویرایش پروفایل استفاده کنید. ارسال بخشی از فیلدها کافی است:

```http
PUT /api/auth/profile/
Authorization: Bearer <token>
Content-Type: application/json

{
  "card_number": "6037991234567890"
}
```

نکات اعتبارسنجی:

- فقط رقم پذیرفته می‌شود؛ بین **۱۶ تا ۲۰ رقم**.
- ارقام فارسی و فاصله/خط تیره هم قبول است و سرور خودش به عدد انگلیسی تبدیل می‌کند. مثلاً `۶۰۳۷ ۹۹۱۲ ۳۴۵۶ ۷۸۹۰` ذخیره می‌شود به‌صورت `6037991234567890`.
- در خطای اعتبارسنجی، پاسخ ۴۰۰ به این شکل است:

```json
{
  "card_number": [
    "شماره کارت باید فقط شامل عدد و بین ۱۶ تا ۲۰ رقم باشد."
  ]
}
```

## ۲) درخواست برداشت

### مالک باشگاه

```http
POST /api/owner/withdraw-request/
Authorization: Bearer <token>
Content-Type: application/json

{
  "amount": "500000",
  "card_number": "6037991234567890",
  "description": "تسویه هفته اول"
}
```

### مربی

```http
POST /api/trainer/withdraw-request/
Authorization: Bearer <token>
Content-Type: application/json

{
  "amount": "500000",
  "card_number": "6037991234567890"
}
```

قواعد مهم:

- `card_number` در بدنه درخواست **اختیاری** است.
- اگر کاربر قبلاً شماره کارت را در پروفایل ذخیره کرده باشد، نیازی به ارسال دوباره آن نیست.
- اگر شماره کارتی ارسال شود، روی پروفایل کاربر ذخیره می‌شود و سپس درخواست برداشت ثبت می‌شود.
- اگر نه در پروفایل شماره کارت وجود داشته باشد و نه در بدنه ارسال شود، پاسخ ۴۰۰ برمی‌گردد:

```json
{
  "card_number": [
    "برای ثبت درخواست برداشت، ابتدا شماره کارت خود را در پروفایل ثبت کنید."
  ]
}
```

### فیلدهای پاسخ درخواست برداشت

همان فیلدهای قبلی هستند؛ تغییر حذفی یا تغییر نام نداشته‌اند. فقط توجه کنید که شماره کارت در مدل درخواست ذخیره نمی‌شود و در پروفایل کاربر نگهداری می‌شود.

## ۳) پنل ادمین

در پاسخ لیست و جزئیات درخواست‌های برداشت، فیلد `card_number` اضافه شده است:

- `withdraw-requests/`
- `withdraw-requests-detail/<id>/`
- `trainer-withdraw-requests/`
- `trainer-withdraw-requests-detail/<id>/`

نمونه:

```json
{
  "id": 31,
  "user": 12,
  "amount": "500000.00",
  "status": "pending",
  "card_number": "6037991234567890"
}
```

## کارهایی که فرانت باید انجام دهد

1. در صفحه پروفایل، فیلد «شماره کارت» را اضافه کنید.
   - `inputmode="numeric"`
   - `maxlength="20"`
   - راهنمای زیر فیلد: «۱۶ تا ۲۰ رقم»
2. بعد از ورود یا دریافت پروفایل، اگر `card_number` خالی بود و نقش کاربر `owner` یا `trainer` است، یک بنر/پیام نمایش دهید: «برای برداشت وجه، شماره کارت خود را ثبت کنید.»
3. در فرم درخواست برداشت:
   - اگر `card_number` دارد، آن را به‌صورت ماسک‌شده نشان دهید (مثلاً `6037 **** **** 7890`) و امکان ویرایش بدهید.
   - اگر ندارد، فیلد شماره کارت را اجباری کنید.
4. شماره کارت را یا در پروفایل ذخیره کنید یا همراه `POST` درخواست برداشت بفرستید؛ هر دو پشتیبانی می‌شود.
5. خطای ۴۰۰ مربوط به `card_number` را مدیریت کنید و کاربر را به پروفایل هدایت کنید.
6. شماره کارت کامل را در `localStorage` یا لاگ‌های فرانت ذخیره نکنید.

## نکات سازگاری

- کاربران فعلی `card_number = null` دارند؛ تا وقتی آن را ثبت نکنند امکان درخواست برداشت جدید ندارند.
- درخواست‌های برداشت قبلی که در وضعیت `pending` یا `approved` هستند دست‌نخورده‌اند.
- تغییرات برای کلاینت‌های قدیمی غیرشکننده است، به شرطی که کاربر از قبل شماره کارت داشته باشد.
